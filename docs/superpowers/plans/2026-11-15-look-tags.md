# Look Tags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A model's feed learns from her saves and rejections. Gemini tags each reel's visible look (hair, aesthetic, setting). Creators and models get look profiles, and look match reorders a model's feed, proposals and suggestions without filtering anything.

**Architecture:** An editable `look_tags` vocabulary. The existing describe call returns `look_tags` constrained to it. Tags are stored as JSON-array text on posts and candidate reels. A small `look-match.js` computes scores; feed ordering does it in SQL with quoted-JSON `LIKE` matches; proposals and suggestions sort in JS.

**Tech Stack:** Node 20 / Express, Postgres + better-sqlite3 tests, `node:test`, React (CRA), `@google/genai` via `server/gemini-sort.js`.

**Spec:** `docs/superpowers/specs/2026-11-15-look-tags-design.md`

## Global Constraints

- Ranking only, never filtering: no query may drop a row because of look tags.
- Gemini may only return non-`custom` vocabulary values, at most 5. The prompt must state: tag only visible styling (hair, makeup, fashion, aesthetic) and setting; never infer ethnicity, race, age, body type or other personal attributes.
- `custom` tags are manual-only: never in the Gemini schema or prompt.
- Tag storage: JSON array text (e.g. `["brunette","bedroom"]`). Match with quoted values (`LIKE '%"alt"%'`) so `alt` never matches inside another tag.
- A model with no look tags → every score 0 → order identical to today.
- Seed vocabulary:
  - hair: `blonde, brunette, black-hair, red-hair, dyed-hair`
  - aesthetic: `emo, alt, e-girl, girl-next-door, glam, gym, cottagecore`
  - setting: `bedroom, car, outdoors, studio`
- Backfill cost estimate per reel uses the existing `estimateCostUsd({ inTokens: 3400, outTokens: 100 })`.
- Branch `look-tags` off `origin/main` `38d2a74`. Don't commit. Tests: `cd server && NODE_USE_SYSTEM_CA=0 GEMINI_API_KEY= npm test` (baseline: run once first and record the count) and `cd client && NODE_USE_SYSTEM_CA=0 CI=true npm run build`.

## Review Focus

1. **A model with no look tags** gets exactly today's order (Task 4 test `no model tags → order unchanged`).
2. **Gemini returns a tag outside the vocabulary or a custom tag** → it's dropped, not stored (Task 2 test `unknown and custom look tags dropped`).
3. **Substring tags:** a model tagged `alt` must not match a reel tagged `alt-girl` if that tag is added later (Task 4 test `quoted match avoids substring hits`).
4. **The look backfill must never change** `sort_status` or `content_type` (Task 5 test `backfill writes only ai_look_tags`).
5. **Feedback loops:** a model who dislikes one reel from a creator must still see that creator's other reels, ranked lower (Task 6 test `disliked reels sink but remain in results`).
6. **Deleting a vocabulary tag** in use by models or creators doesn't break reads: unknown stored tags are ignored in scoring (Task 3 test `deleted tag ignored in scores`).

**Interfaces:**
- Produces:
  - `reelLookMatch(modelTags: string[], reelTags: string[]) -> number` = |intersection| ÷ |modelTags|; 0 when `modelTags` is empty.
  - `creatorLookProfiles(pool, usernames: string[]) -> Promise<Map<username, Map<tag, share>>>`: share = (sorted reels with the tag ÷ sorted reels) from `posts.ai_look_tags` (sort_status auto/manual, not deleted); manual `creator_look_tags` set the share to 1.0.
  - `creatorLookMatch(modelTags, profile: Map<tag, share>) -> number` = mean of `profile.get(t) || 0` over `modelTags`; 0 when `modelTags` is empty.
  - `candidateLookProfile(reels) -> Map<tag, share>` (same idea from `suggested_reels.ai_look_tags`).

**Interfaces:**
- Consumes: `parseTagList`, Task 3/4 scoring.
- Produces:
  - `featuresOfPost(post) -> string[]`: `type:<content_type>` (if any), `tag:<t>` for each `ai_look_tags`, `creator:<lower handle>`.
  - `affinity(pos, neg) -> number` = `(pos - neg) / (pos + neg + 2)`.
  - `recomputeTaste(db, modelId) -> Promise<{ features: number }>`: gathers her saved + `want_to_make` posts (+1 each; a post both saved and want_to_make counts once) and `not_my_style` posts (−1), counts features, then replaces her `model_taste` rows in one transaction.
  - `loadTaste(db, modelId) -> Promise<Map<feature, affinity>>`.
  - Feed: `buildMeFeedQuery(niches, { ..., lookTags, taste })`, where `taste` is `{ types: [[value, aff]], tags: [[value, aff]], creators: [[handle, aff]] }` (top 20 by |aff| per kind, from `loadTaste`). When not shuffled, ORDER BY `(<look match sum> + <taste sum>) DESC, posts.posted_at DESC`. The taste sum is built from `CASE WHEN` terms with params in ascending order. An empty taste and empty look tags must produce exactly today's `ORDER BY posts.posted_at DESC`.
